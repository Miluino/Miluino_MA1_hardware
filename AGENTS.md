## Триггер загрузки контекста

Если сообщение пользователя содержит фразу `проанализируй контекст` без учёта регистра и завершающей пунктуации, начни read-only загрузку контекста этого репозитория. Не проси повторно указать путь к проекту.

Эта фраза разрешает только чтение инструкций, документации и состояния Git. Она не разрешает изменять файлы, запускать Altium Designer, сборку, ERC/DRC, прошивку, тесты, изменяющие Git-команды или внешние операции.

## Минимальный обязательный контекст

По триггеру всегда прочитай только:

1. `D:\Job\18shka\Miluino\dev-guidelines\ai-agents.md`;
2. текущий `AGENTS.md`;
3. `README.md` этого репозитория;
4. результат `git status --short --branch` этого репозитория.

Не загружай автоматически все файлы из `docs`, `codex`, `datasheets`, `Source Documents`, `Libraries` или других каталогов. Не выполняй рекурсивное чтение Markdown-файлов и поиск по содержимому всего репозитория без конкретной причины.

Если вместе с триггером пользователь не указал тему, остановись на обязательном контексте. Кратко сообщи, что README и состояние репозитория прочитаны, а тематические документы будут загружены после постановки конкретной задачи.

## Маршрутизация тематического контекста

Если в сообщении вместе с триггером указана тема либо сразу поставлена конкретная задача, сначала используй `rg` по заголовкам и ключевым словам, затем прочитай только относящиеся к задаче разделы следующих документов.

| Тема | Основные документы |
|---|---|
| Карта выводов К1986, Arduino, STMorpho, AREF, MODE, селекторы и резисторы вариантов | `docs/MDR32_MILUINO_pin_mapping.md` |
| Встроенный CMSIS-DAP, XP5–XP9, XP7/XP8, ARM 10-pin, SWD/JTAG, VCP, SWO и MCO | `docs/CMSIS_DAP_rework.md`, затем при необходимости `docs/STM32F103_DAP_pinout.md` |
| Питание DAP/target, VTref, nRESET, USB-C DAP и `+3V3_DAP_OUT` | `docs/CMSIS_DAP_power_reset_questions.md` и только связанные разделы `docs/CMSIS_DAP_rework.md` |
| Распиновка и обвязка STM32F103CBU6 | `docs/STM32F103_DAP_pinout.md` |
| Согласованные, но ещё не внесённые изменения | `docs/future_changes.md` |
| Общий исторический контекст | `docs/PROJECT_CONTEXT.md` только если актуальных документов недостаточно |
| Первоначальная постановка | `docs/Первоначальный промт.md` только по прямой просьбе пользователя или для выяснения происхождения старого решения |
| Параметры микросхем | сначала соответствующий индекс в `codex`, затем только нужные страницы первичного файла из `datasheets` |

Если задача затрагивает несколько тем, загружай документы последовательно по мере необходимости. Не открывай следующий документ, пока текущий документ и точечный поиск не показали, что дополнительный источник действительно нужен.

## Правила чтения крупных документов

- Сначала найди подходящие заголовки и строки командой `rg -n`.
- Читай найденный раздел и необходимый соседний контекст, а не весь файл.
- Полностью читай крупный документ только при прямой просьбе о полном аудите либо когда вывод зависит от нескольких удалённых друг от друга разделов.
- Для Altium-файлов сначала определи точное имя затрагиваемого `.SchDoc`, `.PcbDoc`, `.SchLib` или `.PcbLib`; не открывай все документы проекта и библиотеки.
- Не считай `docs/PROJECT_CONTEXT.md` или `docs/Первоначальный промт.md` первичным источником при наличии более актуальной схемы, `docs/MDR32_MILUINO_pin_mapping.md` или профильного DAP-документа.
- Не анализируй бинарные библиотеки, datasheet целиком, сгенерированные файлы и кэши без прямой необходимости.

## Приоритет источников

При противоречии используй следующий порядок:

1. текущий явный запрос Романа;
2. актуальная принципиальная схема;
3. `docs/MDR32_MILUINO_pin_mapping.md`;
4. профильные документы `docs/CMSIS_DAP_rework.md`, `docs/CMSIS_DAP_power_reset_questions.md` и `docs/STM32F103_DAP_pinout.md`;
5. `README.md`;
6. `docs/PROJECT_CONTEXT.md`;
7. история обсуждений и `docs/Первоначальный промт.md`.

Если противоречие влияет на аппаратное решение, не выбирай вариант молча: перечисли варианты и запроси решение Романа.
